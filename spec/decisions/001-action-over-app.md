# ADR-001：首版采用 GitHub Action，而不是常驻 GitHub App

- 状态：Accepted
- 日期：2026-08-14
- 范围：运行形态

## 背景

个人项目需要先验证风险分析协议、规则质量和用户反馈。直接引入 GitHub App、常驻服务、数据库和队列会把部署、鉴权、租户和运维复杂度带入尚未验证的核心问题。

## 决策

首版采用 GitHub Action + Go CLI/库：

- 由 `pull_request` 触发。
- 以单次运行完成采集、分析和报告。
- 使用 Artifact 和一条幂等评论交付结果。
- 核心领域对象不依赖 GitHub Action，未来可以被 App/Webhook 适配器复用。

## 原因

- 易于安装和演示。
- 不需要维护常驻服务器和数据库。
- GitHub 已提供事件、Token、Artifact 和评论接口。
- 便于使用本地 event/diff 做离线复现和测试。

## 代价

- 每次运行没有跨 PR 历史状态。
- 大 PR 和大量仓库并发会受 Runner、API 和模型预算限制。
- Fork PR 的 Secret 和评论权限需要单独设计。
- 未来 App 化可能需要增加异步和持久化适配层。

## 退出条件

只有当以下需求真实出现时，才重新评估 GitHub App：

- 跨仓库统一安装和配置。
- 需要保存长期历史风险。
- Action 的运行时长或并发成为瓶颈。
- 需要组织级预算、队列和审计。
